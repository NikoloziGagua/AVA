# Strategy Room

Strategy Room is AVA's persistent, attributed planning workspace for Niko, AVA
and real external agent sessions. The first release connects AVA's configured
LLM provider and a dedicated resumable Codex CLI thread. Claude and Forge are
future adapters; this slice does not modify either system.

## Product contract

- AVA remains the facilitator and routing authority.
- Niko can add context at any time. A message interrupts the current generation,
  becomes durable shared context, and starts a fresh bounded round.
- An existing AVA chat can be moved into a room from the chat screen. The
  browser sends only the session id; the server creates a sanitized, attributed
  snapshot through the latest persisted message. Repeating the same handoff is
  idempotent, while a later chat turn can start a new room.
- Every public message is attributed to `niko`, `ava`, `codex`, or `system`.
- Codex is a real `codex exec --json` thread, not text generated by AVA and
  labelled as Codex.
- Codex runs with `read-only` sandboxing and `never` approval policy. The adapter
  never supplies a dangerous bypass flag and strips API-key environment
  overrides so it uses the owner's existing Codex login.
- Hidden reasoning is not stored or displayed. The adapter consumes only public
  `agent_message` events plus aggregate usage.
- Approving a conclusion records a decision only. It cannot start a coding job,
  self-improvement, Forge run, or other side effect.
- For a chat-linked room, Niko can explicitly return an approved conclusion to
  the originating chat. AVA appends one labelled proposal and asks Niko for the
  course of action. The return does not submit a new user turn, run tools, or
  start implementation.
- Stored room content and event payloads pass through AVA's secret scrubber.

## Bounded round

Each round contains a fixed sequence and then stops:

```text
Niko topic/context
  -> AVA initial position
  -> Codex critical review
  -> AVA cross-review
  -> Codex final recommendation (same Codex thread)
  -> AVA living-brief synthesis
  -> waiting for Niko
```

There is no autonomous agent-to-agent loop. Niko either approves the proposed
conclusion, adds another message, pauses the room, or explicitly reopens it.

## Persistence

`strategy_rooms` stores the current projection: phase, active participant,
version, living brief, conclusion, Codex thread id, errors, approval state, the
optional source chat/message snapshot anchor, and the optional returned chat
message id/time.

`strategy_messages` is the immutable attributed conversation ordered by a
room-local sequence.

`strategy_events` is an append-only global cursor journal used by the
authenticated SSE stream. SQLite is authoritative; process-local subscribers
only remove delivery latency. Clients reconnect using `after=<seq>`.

Rooms left in `discussing` after a server restart are reconciled to `paused`
with an explicit interruption reason. They never remain falsely active.

## API

All routes require AVA device authentication.

- `GET /api/strategy/meta`
- `GET /api/strategy/rooms`
- `POST /api/strategy/rooms`
- `POST /api/strategy/rooms/from-chat`
- `GET /api/strategy/rooms/:id`
- `POST /api/strategy/rooms/:id/messages`
- `POST /api/strategy/rooms/:id/pause`
- `POST /api/strategy/rooms/:id/resume`
- `POST /api/strategy/rooms/:id/approve`
- `POST /api/strategy/rooms/:id/return-to-chat`
- `GET /api/strategy/stream?after=<seq>`

Pause, resume and approval use an expected room version so a stale browser
window cannot mutate a room whose state has changed. Niko messages are
append-only and safe to accept while agents are active; the coordinator aborts
the old generation and rejects its late output with a generation guard.

`from-chat` derives all copied context from authoritative server-side session
rows. It accepts no browser-supplied transcript. Its stable identity is
`(source_session_id, source_through_message_id)`. `return-to-chat` requires an
approved conclusion, a live source chat, and the expected room version. A
repeated return resolves to the original message id and never duplicates the
conclusion. Reopening a returned room permits another round; a newly approved
conclusion may then be returned as a new, clearly dated chat entry while the
old historical entry remains unchanged.

## UI

The `Room` item in AVA's persistent navigation opens a desktop-first three-pane
surface:

1. Room creation and history
2. Attributed shared conversation and Niko composer
3. Participant status, Codex thread identity, living brief and decision controls

An established typed chat shows **Take to Room** while no task is running. Niko
can instead say “take this conversation to the Room” or “bring Codex into this
discussion”; `strategy_room_open` uses the same server-authoritative path and
the UI follows the successful tool event into the linked room. A linked room
identifies its source snapshot and provides **Back to chat**. After Niko
approves the room's conclusion, **Return conclusion to AVA chat** adds the
proposal and navigates to the exact source conversation so Niko can issue,
revise, or reject the course of action.

The screen uses authenticated fetch-SSE rather than putting AVA's device token
in a URL. Polling is not the source of truth; an offline indicator and replay
cursor make stale connectivity visible.

## Current boundaries

- A room creates a dedicated Codex thread. The AVA chat is context lineage, not
  a Codex thread: it cannot silently attach to an arbitrary existing Codex app
  conversation, including the chat in which this feature was developed.
- Claude and Forge are not connected in v1.
- AVA provider token/cost accounting is not yet exposed by the common LLM
  provider interface. Codex token usage is retained in Strategy Room events,
  but monetary cost is not inferred.
- The living brief is Markdown generated by AVA and remains a proposal until
  Niko approves it.
- There is intentionally no "implement" control in v1. A future handoff must be
  a separate, risk-scoped endpoint with its own owner, task id and evidence.
- The linked-chat return is deliberately not that implementation handoff. It is
  a persisted proposal only. Niko's next chat message is the first possible
  instruction, and normal AVA approval/tool boundaries still apply.

## Verification

Focused tests cover storage/redaction, restart recovery, version-guarded
approval, Codex JSONL parsing, reasoning exclusion, persistent Codex thread
reuse, bounded orchestration, Niko interruption, route boundaries and UI
approval/interruption behavior. The installed Codex CLI was also smoke-tested
with a new read-only JSONL thread and a resume turn.

The linked-chat slice additionally tests server-derived attribution and secret
scrubbing, legacy database migration, snapshot deduplication, source isolation,
approval before return, version guards, duplicate return idempotency, exact
chat navigation, and the absence of an automatic execution turn.
